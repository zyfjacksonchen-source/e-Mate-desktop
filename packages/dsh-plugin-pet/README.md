# e-Mate Xiaoxin pet

Presentation-only adaptation of pinned MIT dsh-pet. It occupies the existing `shell.overlay` / `shell.overlay.pet` seats and writes only explicit toggle/position changes through native `settingsScope`. Default disabled, 112 CSS px. Settings: 智能伙伴 → 启用小芯. Pointer dragging and arrow keys move it; Shift moves faster. Clicking opens the current native task's shared details through one Shell callback.

The package subscribes to `ctx.sessions.list`, the selected `binding(id).session`, native `goal`, `todos`, `eMateImageReceipts` and `eMateImageBatches` faces, and `jobsBySession`. Shell derives work facts from these owners through a read-only Cordis callback. Classification uses exact native Tool identities and typed presentation/results; it never reads prompts, token/reasoning text, command arguments, titles, document bodies or DOM text. Explicit web search, grep/glob, supported CDP browser actions, code-file write/edit locations, and exact image receipts supply factual status labels, not fixed animation choices. Browser typing does not imply form filling. Generic read/search cards, Skill loading, and terminal commands do not imply a document, build, test, debug or analysis task.

Top-level Office results retain only operation, format, Job identity, final workspace-relative path and byte count in native `tool/result.meta`. A successful current-turn result can show a **recently completed** Office category; the label does not claim it is still running. Office delivery uses the final collision-resolved result path, never its call-time requested path. Code Mode lacks this canonical presentation metadata at the pinned baseline, so its Office subcalls remain generic. Successful images remain usable in a partial batch, but partial/unknown outcomes do not become whole-batch success; unknown/review states request attention, while actual failures retain error state. Unproven office purposes remain generic even if artwork exists.

Waiting/approval → error → current Tool/Job/Todo → Goal → queue → recent completed operation → deliverable → idle is retained for factual status labels with 750 ms minimum residence. Route changes never retain another task's status or detail target.

Visible actions are independent of task type. The overlay moves through a shuffled repertoire every 16–24 seconds without repeating an action within a cycle; the cycle boundary also avoids immediate repeats. Each action plays once at 0.4× the atlas speed, then holds its final pose until the next action. Pausing preserves progress instead of replaying the action. Error/approval poses are not chosen as decorative actions. Dragging overrides the pose, and menus, first response, hidden/minimized windows and reduced motion pause the free-action timer. The next task does not force the same task-specific pose again.

Shell integration supplies `ctx.ematePetDetails.openTaskDetails(taskId)` and `readWorkFacts(sessionId)` from `createPetWorkFactsReader(ctx)` in its `pet-image-facts.ts` adapter. Register them on the existing shared structured-details owner. The service's lifecycle owns the pet's detailed subscriptions. No model Tool, Job, Session event, parallel state store or additional transport is created by this package.

Assets load in idle time only when enabled, visible and outside first response. They use fixed same-origin URLs, bounded reads, SHA-256 and decoded geometry validation. Browser visibility/focus (including hidden/minimized windows), reduced motion and first response stop animation timers. Disabled/hidden pets detach detailed Session subscriptions. Disposal aborts loading, unsubscribes native faces, clears timers and revokes object URLs. Explicit retry recovers resources without a polling loop.

The package includes the official Xiaoxin standard v2 atlas (nine animation rows and sixteen look directions) and thirty independently generated eight-frame office scenes. Exact manifests, hashes, dimensions and pixel checks passed, followed by independent direction/scene reviews and a local 112px check using the real renderer. Ambiguous small props are accompanied by factual accessible state labels; the presence of an animation does not prove an unsupported operation occurred. See `assets/PRODUCTION.md`. Full Desktop integration, dual-platform installation and performance acceptance remain required before release. Missing art can still compile during development, but the native packaging gate rejects absent required assets.
