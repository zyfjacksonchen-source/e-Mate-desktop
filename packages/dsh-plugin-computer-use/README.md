# @e-mate/dsh-plugin-computer-use

Computer Use is exposed only when the current user request explicitly inserts `@电脑操控`. The visible user message keeps that exact label instead of an internal activation marker. The model cannot enable it on its own, and a grant from a prior turn is not reused. Webpage work uses the CDP browser adapter first.

This package embeds the exact MIT-licensed `Anionex/dsh-computer-use` commit recorded in `SOURCE.md` and adapts its bundle identity to e-Mate 2.0.18 on Harness 0.1.5-rc.1. Its Windows backend incorporates only the audited MIT Win32 primitives and exact blobs recorded there. Both platforms stay on the same native DSH Tool, Skill, Settings, approval, storage, attachment, subprocess, Service, and Profile owners.

Darwin uses the pinned Accessibility/CoreGraphics provider, with exact-window screenshot validation and zero cursor-animation wait in the shipped Profile. Win32 selects one UI Automation backend. Both platforms preserve foreground focus by default and keep the existing Tool, permission, lease, Job, Attachment, and per-turn explicit `@电脑操控` owners.

Windows compiles its packaged helper once per lazy subprocess generation and uses serial, bounded JSONL requests with a version handshake and exact response IDs. Cancellation, timeout, framing failure, replacement, and disposal terminate and reap that subprocess tree. A new generation verifies the helper hash and handshakes again; failed actions are never replayed automatically.

Windows background actions use UIA Invoke, Value, Toggle, SelectionItem, ExpandCollapse and Scroll patterns. Checked native Edit/RichEdit controls support targeted text and bounded navigation keys; a limited set of native controls supports directed scroll messages. Custom/WebView keyboard delivery, clipboard shortcuts and background raw pointer/drag input fail closed. Raw pointer fallback requires the exact target already be foreground, an explicitly selected route, and a checked native child HWND. No fallback activates the target, moves the system cursor, uses global input, or reads/writes the clipboard. An application can still change its own foreground state as an action side effect; Windows reports that race as unverified.

Private executable path, process start time and HWND remain object-identity sidecars. Observation and action revalidate the exact target and current state hash. UIA properties are fetched in batches within each fresh observation; cached elements never survive an observation, and toggle/selection/expansion/scroll state participates in the result. Captures use the exact selected window (`PrintWindow` on Windows, ScreenCaptureKit window ID on macOS), never a screen crop or a different same-process window. Windows capture failure/minimization fails closed; API success alone is not evidence that a protected or custom renderer produced useful content. Per-monitor-v2 DPI and original macOS coordinate calibration remain native concerns.

Source tests and local helper compilation do not establish real-machine latency, focus/cursor/clipboard preservation, installation or release acceptance. Those gates require the two native machines and the exact final source.
