# Upstream source and e-Mate integration

This component vendors host execution code from [dickpy/dsh-imagegen](https://github.com/dickpy/dsh-imagegen), version **1.5.11**, commit **1f0ec46bdc477835202d9d497744eaa18692b4e0**, under **Apache-2.0**. The upstream license is preserved as `LICENSE`. `upstream-manifest.json` records original and adapted SHA-256 values for every vendored file.

The original request shaping, generated-image normalization, host task queue, and agent tool definitions are the implementation. This package does not import the upstream plugin bootstrap, browser studio, sidebar entry, standalone gallery/canvas, settings pages, model catalogs from remote services, prompt/template synchronizers, or updater. The existing e-Mate conversation, gallery and canvas remain the presentation owners.

The marked changes to vendored files are limited to:

- `engine.ts`: an injected request function routes through the existing enterprise identity service; Blob inputs use a concrete Uint8Array for the pinned TypeScript/Node contract. The generic edit multipart path forwards all host-validated sources instead of silently truncating after five. Parallel single-image requests use `Promise.allSettled` so all admitted resources settle and successful images survive another request's failure. No retry, fallback model or replacement image is added.
- `generation-runtime.ts`: requires a host history sink instead of importing the upstream standalone disk history; accepts a per-request channel resolver and its authenticated transport. Native attachment CAS plus Session receipts persist e-Mate output; no second history index is created.
- `task-queue.ts`: exposes resource settlement for native Job cleanup, releases generated/source bytes after native persistence, and permits eviction of old terminal cache entries. Its existing four-slot budget counts each task by its `n` provider requests, preventing a four-task by four-output fan-out of sixteen. The upstream queue still owns queued/running/completed/failed/cancelled transitions and cancellation. Partial failures are retained beside actual outputs, including successful admitted requests that settle after cancellation.
- `agent-image-tools.ts`: adds an explicit native host seam for submission, task ownership, source access and image materialization; declares concurrent-safe leaf tools with the existing upstream generation deadline; rejects counts outside 1–4 and parameters unsupported by the fixed enterprise route; exposes the upstream multi-image request capability through mutually exclusive `source_image`/`source_images` inputs; returns explicit requested/returned/failed counts. After materialization it reads the host's durable result so validation failures remain consistent across the original call and later task queries. Its model result remains JSON text containing image references; presentation metadata remains display-only.
- `protocol.ts`: adds an internal correlation field to generation requests and partial request errors to results. Neither becomes a provider image parameter.

`image-format.ts` and `model-catalog.ts` are byte-for-byte upstream source. The host adapter only configures `gpt-image-2.5-flare`; other families retained in the upstream engine are unreachable through this package's tools.

The `src/host.ts` and `src/index.ts` e-Mate adapter uses the pinned rc.7 Tool, Job, Attachment and Session seams. It preserves enterprise model authorization and request receipts, checks current-session image ownership, binds PTC sub-call results to the real root Tool call/turn, emits version 3 `emate/image-output` events with actual image refs, and bounds the completed in-memory cache to 256 entries. Older task results remain queryable from the owning Session's durable receipts after cache eviction or a host restart. A task that was still running before restart is reported as unconfirmed; it is never automatically submitted again.

The host maintains native aggregate attachment count/byte validation and saves each output through native `saveImage`, preserving valid outputs when another output fails decoding or storage. Every provider HTTP request uses its own matching task/trace/client ID so the existing gateway can authorize and finalize each request independently. Durable `request_receipts` retain actual gateway response IDs and optional returned-image SHA-256 values for attachment correlation, without inventing a billing state.

Verification runs against the pinned native Tool/Job/Attachment/Session implementations with fixture images, plus the actual local model-gateway router and usage store with a fixture provider. The gateway test covers generation, multi-source editing, unsupported parameter rejection and separate per-request usage finalization. No live provider call or installed application acceptance is asserted by these tests.
