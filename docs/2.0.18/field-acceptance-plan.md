# 2.0.18 实机验收计划（本机 macOS + Windows 候选）

本文件把用户提出的三条验收要求落成可执行的用例与判定口径：**2.0.11 之后所有改动过的点重新检验**、
**性能实测并与 DSH 原版对齐**、**由 Agent 自行登录测试账号完成实机测试**。执行结果另记
`docs/2.0.18/field-acceptance-receipt.md`，本文件只定义方法与判定。

## 1. 候选与环境

| 项 | 要求 |
|---|---|
| 候选 | macOS 与 Windows 必须是**同一源码、同一组不可变字节**；两者都构建完成后才允许开始实机阶段 |
| 身份 | 每个用例记录：版本、源码 HEAD、Harness SHA（= gitlink = 子模块 HEAD）、未签名候选 SHA-256、安装后可执行文件 SHA-256、Profile generation、平台/架构 |
| macOS 环境 | 本机 macOS（`sw_vers` 记录实际 build），arm64 原生；Rosetta x86_64 路径单独记一条 |
| Windows 环境 | 既有 win-codex 通道的远程 Windows 11 x64 主机；远程不可用时 Windows 记 `OPEN`，不阻塞 macOS 结论，也不得声称跨平台通过 |
| 状态隔离 | fresh 安装一套；从已装 2.0.17 升级一套（预置会话/项目/模型/设置/Skill/MCP/记忆/Schedule/附件）。两套互不污染 |
| 定位 | 两个包共用 bundle id `net.ecoremedia.e-mate`，Computer Use 必须按候选的**绝对 .app 路径**定位，防止误测旧 RC |

## 2. 登录（由 Agent 自行完成）

本机已有测试账号 `candidate_2018`（org `candidate-test`）的登录态，私有凭据在 0600 文件与原生登录流程中，
**绝不粘进会话、日志或回执**。需要重新登录时由 Agent 用既有私有文件与原生登录流程完成，回执只写

## 3. 回归面：2.0.11（`6a7f4b9d`）之后所有改动过的点

来源是 `docs/2.0.18/regression-ledger.json`：`6a7f4b9d..3cc4be84` 共 411 提交、236 条修复。
不需要逐条在 GUI 上点一遍——**判定口径是"每条修复要么有实机可观察的用例，要么有已执行的非 UI 门禁，
要么有明确 disposition"**，三类互斥且必须覆盖全部 236 条：

1. **实机可观察（GUI 用例）** —— 由实存守卫文件覆盖的行为，按下面的分组逐条执行。
2. **非 UI 门禁已执行** —— 组件门禁、`test:fast`、`test:image-evidence`、enterprise、desktop `yarn check`；
   已在 `63` 提交后的门禁终态里实测为 EXIT 0，实机阶段只需**复跑一次**以证明安装候选的来源一致。
3. **disposition** —— 随功能移除的（18 条中已定性的那些），实机阶段只核对"该能力确实不再存在"，
   例如 Computer Use 的入口、包与 `@电脑操控` 触发器必须都已消失。

实机用例按 area 分组（每组的结果独立记录）：

| 组 | 覆盖 | 关键断言 |

## 4. 性能：与 DSH 原版对齐

**对照设计。** e-Mate 候选与 DSH 原版跑的是**同一个 Harness 提交**（`43c411a5`），所以差异只可能来自
e-Mate 的 Profile 与其插件。对照取固定版 Harness 自带的 profile（`upstream/deepseek-harness` 原样启动），
处理组取安装后的 e-Mate 候选；同机、同网络、同模型、同提示词。

**三个必测维度：**

**计时来源（第 18 轮定稿，实测过可用性）**：

- 会话日志 `~/.dsh/sessions/<workspace>/<session>/session.v3.jsonl.zstd` **不可直接解析**：该文件是多帧追加写入，
  `zlib.zstdDecompressSync` 只出第一帧、`createZstdDecompress()` 流式读到第二帧即 `Unknown frame descriptor`（实测）。
  因此**不把会话日志当作计时来源**。
- `storages/emate_task_audit.json`（6.2 MB）与 `emate_weekly_quota.json` 里**没有任何 ms/duration 字段**（实测键名扫描为空）——
  它们只记账号/任务绑定与用量。
- **采用外部计时 + 界面终态判定**：由 Agent 以固定节奏（100 ms 轮询 AX 树/截图）测量
  ①"发送→首个助手文本可见"= 首响；②"发送→该轮 turn-tail 显示完成/耗时"= 每轮总时长；③生图 = "发送→结果图片可见"。
  每条样本记录：提示词、开始/结束 ISO 时间、轮询次数、命中判据；中位数与 p95 由样本直接算出，脚本与原始样本一并留档。

| 维度 | 测量方式 | 统计 |
|---|---|---|
| 生图延迟 | 从工具调用发起到收到终态回执；用会话里 `emate/image-output` 回执已有的阶段时间戳（provider submit/finish、CAS begin/end、tool return），而不是外部计时 | 3 次预热 + 10 次采样，报 p50/p95 与对照比 |
| 首响（TTFT） | 发出一条固定提示词到第一个可见 token 的时间；同时记录原生 turn-tail 里的 `ttftMs` 作为交叉验证 | 同上 |
| 多轮对话后的响应 | 连续 8 轮的每轮总时长与每轮 TTFT，重点看**第 8 轮相对第 1 轮的劣化**（上下文增长导致的滑落） | 报每轮 p50 与首末轮比值 |

**判定口径。** 每一项给出"对照值 / 处理值 / 比值"。判定为**大致对齐**要求：
- 中位数比值在 `0.8–1.25` 区间内，且 p95 比值不超过 `1.5`；
- 多轮劣化（第 8 轮 / 第 1 轮）不得比对照差 `25%` 以上。

超出即记 `NEEDS_EVIDENCE` 并附采样数据与可能的成因，**不得**用"感觉差不多"结案。
若某项无法与对照同条件比较（例如对照侧没有等价的 GUI 入口），必须写明原因与所选的替代比较方式，
不能略过。

**限额处理（用户已授权）。** 生图与对话都依赖上游模型。一旦遇到上游限额/配额拒绝：
1. 立即停止该维度的继续采样，已完成的样本原样保留；
2. 该维度记 `BLOCKED(upstream-quota)`，写明 stopped_at、已完成样本数与是否仍能得出趋势；
3. **不得**改用其他模型、其他渠道或本地桩来"补足"样本，也不得把受限记成通过；
4. 其余不依赖该上游的维度（如不调用模型的 UI 用例、非 UI 门禁）继续执行。

## 5. 判定与回执

结果只允许 `PASS / FAIL / BLOCKED / NEEDS_EVIDENCE / OPEN / OUT_OF_SCOPE`。
任一 `FAIL`、崩溃、状态丢失、重复执行、越权、假成功、凭据泄漏或候选字节漂移 → 整体 `BLOCKED`。
`BLOCKED` 不能被源码测试、fixture、截图或旧候选回执替代。

每条回执至少含：候选身份、环境、操作证据（case ID、开始/结束时间、关键步骤、操作前/中/后 AX 状态与关键截图）、
终态证据（脱敏后的 Session/Job/Tool/Attachment ID 与实际结果）、失败证据（稳定 stage/code、是否可重试、恢复结果）、
判定与执行人。**不记录** token、密码、用户内容或私有绝对路径。

## 6. 本文件不声称什么

本文件只是计划：它不声称任何候选已经构建、安装或验收，也不声称任一平台通过。在
`field-acceptance-receipt.md` 写出真实回执之前，2.0.18 的实机状态一律为 `OPEN`。
